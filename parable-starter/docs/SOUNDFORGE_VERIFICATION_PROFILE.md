# Soundforge full verification profile — version 1

This is the reusable minimum contract for a standalone circuit assignment, not
permission to change its issue-specific gates or claim musical/hardware approval.
The assigned issue, Constitution and AGENTS remain authoritative. Record each gate
as passed, failed, not run or outside scope. An attempted failure is not missing
work; a cached receipt is not a current-head execution. Keep original thresholds,
fixtures, case IDs, reference versions, goldens, source notices and failed results.

## Gate 0 and iteration

Start from the required current main; inspect live issues/PRs without importing
unmerged work. Read project rules/status and circuit decisions. Audit and pin
credible physical sources and actually inspect eligible upstream code before
inventing; retain exact revisions, files, licenses/notices and rejected candidates.
The registry's current MIT/BSD-2 import policy remains unchanged. Distinguish a
schematic reference from a code license and a nominal device from calibration.

Before editing, run one clean full Debug and Release baseline; record CTest
inventory/commands, per-test wall and CPU time, machine/quota/affinity, compiler,
dependency/source/fixture hashes and actual outcomes. Predeclare the assignment's
scientific, safety, alias, memory/work and resource thresholds. Use targeted tests
while iterating, then one final full suite per configuration on stable code; rerun
a full suite only when a subsequent edit affects the coverage it exercises.
Never present a prior-main pass as a current-head pass. Report build, test,
scientific research, render and publication times separately.

## Physical and scientific evidence

Use the same native implementation for the healthy circuit and specified causal
component fault(s). Preserve topology, loading/feedback, bias and relevant state;
let the electrical change determine the audible result. Identify the changed part,
orientation, units/value, current/charge behavior, unchanged parts and omissions.
No arbitrary gain, gate, noise or numerical failure masquerades as a physical fault.

Run the full source-independent DC/current/KCL, transient/history, control/load/
supply/temperature and harmonic/phase/frequency checks required by that circuit.
Commit literal independently runnable netlists/conditions, simulator pins and
hashes, points/cases, measured errors and tolerances. Native stamps/output are not
independent expected truth. Keep divergent references/failures visible. Compare
sample-rate/oversampling alternatives to converged independent or finer numerical
truth; report nonconvergence and distinguish intended harmonics from alias spurs.
Do not bless a filter or looser limit because it hides a discrepancy.

## Safe native execution and listening

Preserve bounded allocation-free, IO-free, lock-free and exception-free callback
work; audit the reachable implementation, not just a header or undefined-symbol
list. Exercise preparation/rejection without damaging the active object, stop,
reset, invalid controls, nonfinite/extreme audio, supported rate endpoints,
determinism, long notes, release/silence and actual failure containment. Retain
sample-level guards and all original assertions unless an independently reviewed
proof-preserving replacement is explicitly justified.

Use the required licensed/owned same-take guitar, exact prepared-input SHA and full
attribution/change notices. Run actual native dry/healthy/fault WAVs with controls,
calibration and tail recorded. Preserve raw/common gain separately from individual
RMS matching; publish actual float/PCM levels, DC, clips, gains, source identity,
synthetic labels and solver/containment counters. Repeat/reset must meet each
existing bit-identity policy; a source hash alone does not prove behavior. Keep
failed musical hypotheses. Founder listening remains a separate decision.

An unchanged input archive may be reused only after checksum verification and
unchanged source-preparation checks. A rendered-artifact cache, if introduced,
must include exact relevant source, toolchain, dependency, input, parameters and
executable preservation checks in its key/receipts, revalidate all output hashes
and notices, and invalidate on any relevant change. It cannot replace required
current-head scientific/regression execution. No rendered cache is implemented by
SF-TEST-PERF-001.

## Final execution and delivery

Always run the unconditional complete Debug and Release suites. The standard
bounded host schedule is `ctest --test-dir BUILD -j2 --output-on-failure
--no-tests=error`; no `-R`, label exclusions or cached pass in final full execution.
Each build/configuration uses its own evidence/output paths. Keep CPU costs/labels
and two-worker stress-test reservations; do not increase concurrency blindly.
Use `tools/soundforge/benchmark.py` for itemized real full-suite measurements.

Run ASan/UBSan for all affected boundaries (the infrastructure ticket runs the full
suite) and existing TSan concurrency checks where applicable. Record exact flags,
commands, diagnostics and environment limitations; an unstarted or unsupported
sanitizer is not a pass. For verification-infrastructure changes, negative controls
must corrupt an independent reference, audio and an existing golden in isolated
copies and demonstrate the original checks reject them. Keep production sources,
old fixtures/goldens and source notices intact; check symlinks, registry and CI YAML.

Run the pinned full ARM firmware recipe and applicable standalone object/layout/
callgraph/stack audits. Report actual text/data/BSS, instance and static work/stack
limits. Separate object compilation, ELF linking, bootloader compatibility and
physical timing/stack/IRQ/audio proof. Do not infer Seed3 deadline performance from
host timings or a successful link. Do not integrate a standalone specimen by default.

Publish source-reproducible listening artifacts with checksums/provenance and
exact tested/producing identities. Open one unmerged PR with changed-file reasons,
exact commands/results, pre/post times, failed/unrun gates, remote CI job/step
status, assumptions and next smallest action. Keep the PR draft when the assigned
scientific acceptance fails. CI startup failures are a separate infrastructure
blocker; do not remove checks or label unexecuted jobs as code-test failures.
Neither this profile nor an engineering pass grants musical or hardware admission.
